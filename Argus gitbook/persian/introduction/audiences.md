# مخاطبان و کاربردها

## چه کسی از ARGUS استفاده می‌کند؟

| نقش | چرا ARGUS |
|---|---|
| **تیم پاسخ به حادثه (IR)** | بازسازی دقیق خط زمانی نفوذ؛ شاهد دست‌نخورده |
| **تیم انطباق و حسابرسی** | اثبات اینکه سابقهٔ سیستم بازنویسی نشده؛ گواهی یکپارچگی |
| **مدیر سیستم / DevOps** | پایش تغییرات حساس (فایل‌های مجوز، ماژول‌ها) با سربار کم |
| **تیم حقوقی / فارنزیک** | مدرکی که قابل تأیید مستقل با `sha256sum` است |
| **تحقیقات بازار (تیم شما)** | درک تمایز فنی برای مقایسهٔ رقابتی و پیام‌رسانی محصول |

## سناریوهای نمونه

### ۱. پس از یک نفوذ

مهاجم وارد شده، یک بک‌دور نصب کرده و تلاش کرده لاگ‌ها را پاک کند.
با ARGUS:

```bash
argus-cli verify              # آیا زنجیره دست‌نخورده است؟
argus-cli anomalies           # هشدارهای امروز
argus-cli list --sensitive    # دسترسی به فایل‌های حساس
argus-cli integrity --from 09/01/2026 --to 09/30/2026   # گواهی بازه
```

اگر مهاجم خطی را حذف کرده باشد، `verify` عدد `BROKEN LINKS` را نشان می‌دهد؛ اگر محتوا
را عوض کرده باشد، `BAD HASHES`.

### ۲. اثبات انطباق

در جلسهٔ حسابرسی، سؤال می‌شود «از کجا بدانیم این سابقه دست‌کاری نشده؟»

```bash
sudo argus-cli integrity --from 09/01/2026 --to 09/30/2026
# مانیفست SHA-256 تولید می‌شود که حسابرس می‌تواند مستقل تأیید کند
```

### ۳. پایش تغییرات حساس

بدون اینکه درگیر حجم لاگ شوید:

```bash
argus-cli sensitive           # فقط رویدادهای مسیر حساس
argus-cli list --external     # سرشماری بلوک‌های دارای IP بیرونی
```

### ۴. جریان‌دهی به SIEM

```bash
# رویدادهای مسیر حساس با تگ ARGUS_SENSITIVE به SIEM می‌روند
argus-cli export --format json
argus-cli export --format csv   # ستون flags برای مسیریابی
```

## پیش‌نیاز دانش

- برای **اجرا**: آشنایی پایه با لینوکس و خط فرمان کافی است.
- برای **استقرار**: دسترسی root و آشنایی با systemd.
- برای **درک فنی عمیق**: بخش [معماری](../architecture/README.md) و
  [امنیت](../security/README.md) پیشنهاد می‌شود.
