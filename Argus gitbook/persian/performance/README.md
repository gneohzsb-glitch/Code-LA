# کارایی

ARGUS طوری طراحی شده که سربار آن روی سیستم میزبان **حداقلی** باشد و در عین حال سابقهٔ
کامل و دست‌نخورده تولید کند. این بخش اعداد اندازه‌گیری‌شده و منطق ظرفیت‌سنجی را ارائه
می‌دهد.

---

## اصول کارایی

| اصل | چطور |
|---|---|
| کار سنگین در کرنل نیست | حسگر eBPF فقط رویداد خام می‌فرستد؛ منطق در فضای کاربر |
| فیلتر در نزدیک‌ترین نقطه | نویز پیش از رسیدن به بلاکچین دور ریخته می‌شود |
| نوشتن خطی | هر بلوک یک نوشتن append است؛ بدون بازنویسی فایل |
| تجمیع بدون حذف | خواندن‌های خسته‌کننده در یک شمارنده جمع می‌شوند، نه در هزاران بلوک |
| فشرده‌سازی در پس‌زمینه | روزهای گذشته در thread نگهداشت فشرده می‌شوند |

## خلاصهٔ اعداد

| سنجه | مقدار |
|---|---|
| نرخ ثبت (پس از فیلتر) | ~۳۶ بلوک در ۳۰ ثانیه |
| نرخ ثبت (پیش از فیلتر) | ~۳۲۶ بلوک در ۳۰ ثانیه |
| رویداد self-capture | ۰ |
| فشرده‌سازی لاگ یک روز | ۴۶ MB → ۸٫۴ MB (۵٫۴×) |
| `list --external` روی روز ۱۰۹ MB | ~۰٫۶ ثانیه |
| `verify` روی ۳۶۸٬۰۰۰ بلوک | ~۳٫۴ ثانیه |

> این اعداد روی VM مرجع (Ubuntu 22.04، کرنل ۵٫۱۵) اندازه‌گیری شده‌اند و به سخت‌افزار و
> الگوی بار بستگی دارند.
