# verify و integrity

## `argus-cli verify`

تأیید کامل زنجیره: هم **لینک** و هم **هش** هر بلوک بازمحاسبه می‌شود.

```bash
sudo argus-cli verify
sudo argus-cli verify --date 09/30/2026
```

خروجی سالم:

```
  ◆ ALL 368137 BLOCKS VERIFIED — NO BREAKS
```

خروجی با دست‌کاری:

```
  ◆ 18 BROKEN LINKS / 0 BAD HASHES / 126369 BLOCKS
```

| نشانه | معنی |
|---|---|
| `NO BREAKS` | زنجیره دست‌نخورده است |
| `BROKEN LINKS` | یک بلوک جابه‌جا/حذف شده (یا `prev_hash` نمی‌خواند) |
| `BAD HASHES` | محتوای یک بلوک عوض شده ولی هش بازمحاسبه نشده |

> **نکتهٔ مهم:** `verify` فقط لینک‌ها را چک نمی‌کند — **هش را هم بازمحاسبه می‌کند**. پس
> ویرایش محتوا (حتی اگر مهاجم `prev_hash` را درست کند) هم کشف می‌شود.

### اگر رمزنگاری روشن باشد

`verify` روی لاگ رمزشده نیاز به `sudo` دارد (salt فقط root خواندنی است). بدون root،
تعداد بلوک‌های خوانده‌نشده گزارش می‌شود:

```
◆ 237 ENCRYPTED BLOCK(S) SKIPPED
```

### خواندن روزهای فشرده

`verify` روی `.log.gz` هم کار می‌کند و گزارش می‌دهد که فایل فشرده است.

## `argus-cli integrity`

گواهی یکپارچگی برای یک بازهٔ زمانی — یک **مدرک قابل ارائه**:

```bash
sudo argus-cli integrity --from 09/01/2026 --to 09/30/2026
```

خروجی:

```
  ARGUS INTEGRITY CERTIFICATE
  ============================
  Date Range:         09/01/2026 to 09/30/2026
  Total Events:       ...
  Files Verified:     ...
  Chain Hash:         <sha256>
  Verified:           YES - NO TAMPERING
  ============================
  VERIFICATION: sha256sum <log_file> should match hash above
```

مانیفست یک هش SHA-256 برای کل بازه می‌سازد که **حسابرس می‌تواند مستقل با `sha256sum`
تأیید کند** — بدون نیاز به ARGUS.

## `argus-cli anomalies`

هشدارهای امروز:

```bash
argus-cli anomalies
argus-cli anomalies --date 09/30/2026
```

> **v15.4:** این دستور حالا **از روی زنجیره** می‌خواند — همان بلوک‌های تایپ‌شدهٔ
> `{"e":"ALERT"}` / `{"e":"HINT"}` که `argus-cli alerts` می‌خواند، با همان تجزیه‌کننده.
> نسخهٔ قبلی متن خام رویداد را برای رشتهٔ `"ANOMALY"` می‌گشت که **هیچ‌جای کدبیس
> نوشته نمی‌شد** و منطق تشخیص را با regex جداگانه دوباره پیاده کرده بود که از موتور
> هشدار فاصله گرفته بود. الان یک منبع حقیقت است.

قواعد هشدار شامل: brute-force، برداشتن ماژول، افزایش سطح دسترسی، حذف فایل، دست‌کاری لاگ،
شکستن زنجیره، دسترسی خارج ساعات کاری، آتش سریع، رفتار ناهنجار، فشار ذخیره‌سازی، تغییر
حالت فیلتر، و دسترسی به مسیر حساس.

## تفاوت `verify` و `integrity`

| | `verify` | `integrity` |
|---|---|---|
| دامنه | یک روز یا کل سابقه | یک بازهٔ دلخواه |
| خروجی | شمارش شکاف‌ها | مانیفست + هش |
| کاربرد | بررسی سلامت روزمره | مدرک برای حسابرسی/دادگاه |
| نیاز به root | فقط اگر رمزنگاری روشن باشد | بله |

---

## چه چیزی کشف می‌شود؟

| حمله | `verify` چه می‌گوید |
|---|---|
| زنجیرهٔ سالم | `NO BREAKS` |
| ویرایش محتوا (هش دست‌نخورده) | `BAD HASHES` |
| دوباره‌لینک‌کردن بلوک | `BROKEN LINKS` |
| حذف بلوک از میانه | `BROKEN LINKS` |

این چهار حالت در `tests/test_verify.sh` تست می‌شوند.
