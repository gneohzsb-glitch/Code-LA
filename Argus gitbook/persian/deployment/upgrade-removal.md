# به‌روزرسانی و حذف

هیچ‌کدام از این مراحل به ریبوت نیاز ندارد. سپر عمداً سیگنال از PID 1 (systemd) را رد
نمی‌کند، پس مدیر سرویس همیشه می‌تواند دیمن را پایین بیاورد.

---

## به‌روزرسانی معمولی (بدون تغییر سپر)

اگر فقط کد کاربرفضا (دیمن/CLI) عوض شده:

```bash
cd ~/argus_v15
make
sudo ./install.sh
sudo argus-cli service restart
```

`systemctl restart` **رمز نمی‌خواهد** — این همان استثنای PID 1 است.

> ری‌استارت کامل حدود ۴۰ ثانیه طول می‌کشد (thread خط پایه در حال پایان کار است).

---

## به‌روزرسانی کامل (با تغییر سپر)

اگر کد ماژول کرنل (سپر) عوض شده، باید ماژول برداشته و دوباره بار شود. از مسیر رمزدار:

```bash
sudo argus-cli release                   # سپر آزاد + دیمن متوقف (داده‌ها می‌مانند)
cd ~/argus_v15 && make && sudo ./install.sh
sudo argus-cli service restart
```

`release` رمز حذف را می‌پرسد، سپر را آزاد می‌کند، دیمن را متوقف می‌کند و ماژول را
برمی‌دارد. پس از `install.sh`، سپر خودکار دوباره مسلح می‌شود.

---

## تغییر رمز حذف

```bash
sudo argus-cli change-password
```

پس از تغییر، سپر خودش را با توکن جدید هماهنگ می‌کند — نیازی به ری‌استارت نیست (توکن در
هر تلاش بازخوانی می‌شود).

---

## حذف کامل (لاگ‌ها می‌مانند)

```bash
sudo argus-cli remove
```

این دستور:

1. سپر را آزاد می‌کند
2. دیمن را متوقف می‌کند
3. ماژول را برمی‌دارد
4. باینری‌ها و تنظیمات را حذف می‌کند

**پوشهٔ لاگ دست‌نخورده می‌ماند** — حذف ARGUS هرگز سابقهٔ فارنزیک را پاک نمی‌کند.

---

## تفاوت `release` و `remove`

| | `release` | `remove` |
|---|---|---|
| سپر را آزاد می‌کند | بله | بله |
| دیمن را متوقف می‌کند | بله | بله |
| ماژول را برمی‌دارد | بله | بله |
| باینری‌ها را حذف می‌کند | **خیر** | بله |
| تنظیمات را حذف می‌کند | **خیر** | بله |
| لاگ را حفظ می‌کند | بله | بله |
| کاربرد | ارتقا/ری‌استارت | حذف نهایی |

---

## نکات

- `release` و `remove` هر دو رمز حذف می‌خواهند.
- اگر پس از `release` دوباره `systemctl start` کنید، سپر خودکار دوباره مسلح می‌شود.
- برای حذف دستی آرشیوها، اول مهر را باز کنید:
  `sudo chattr -i <path>/DD.log.gz`
- **هیچ‌کدام از این عملیات ریبوت لازم ندارد.**
