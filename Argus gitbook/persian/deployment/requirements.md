## بسته‌های ساخت

برای ساخت از منبع:

```bash
sudo apt-get install build-essential clang llvm \
    linux-headers-$(uname -r) \
    libbpf-dev libelf-dev zlib1g-dev libssl-dev pkg-config
```

| بسته | برای چه |
|---|---|
| `clang` + `llvm` | کامپایل برنامهٔ eBPF |
| `linux-headers-$(uname -r)` | ساخت ماژول سپر |
| `libbpf-dev` + `libelf-dev` | بارگذاری و لینک eBPF |
| `zlib1g-dev` | فشرده‌سازی نگهداشت |
| `libssl-dev` | SHA-256 و AES |

## فضای دیسک

فضای مورد نیاز به **نرخ رویداد** بستگی دارد و از پیش قابل پیش‌بینی نیست. اما:

- روزهای گذشته به‌طور خودکار فشرده می‌شوند (**~۵× کوچک‌تر**).
- هشدار در **۸۵٪** دیسک صادر می‌شود.
- سیاست پیش‌فرض: **هرگز حذف نمی‌شود** (فقط فشرده).

تخمین محافظه‌کارانه: یک هاست پرترافیک می‌تواند روزانه چند صد مگابایت (پیش از فشرده‌سازی)
تولید کند. برای ظرفیت‌سنجی دقیق به [ظرفیت‌سنجی](../performance/capacity-planning.md) رجوع
کنید.

## نکات سازگاری

| مورد | وضعیت |
|---|---|
| SELinux | تست نشده |

| فایل‌سیستم بدون پشتیبانی `immutable` | کار می‌کند؛ مهر اعمال نمی‌شود (best-effort) |
| کانتینر / namespace | خارج از دامنه |
| ماشین مجازی | پشتیبانی‌شده (پلتفرم مرجع تست، VM است) |

## بدون نیاز به تغییر بوت

ARGUS **هیچ** تغییری در GRUB، initrd، یا پارامترهای بوت لازم ندارد. تمام قابلیت‌ها
(حسگر eBPF، سپر کرنل، رمزنگاری) با بارگذاری ماژول و اجرای سرویس در زمان اجرا فعال
می‌شوند. این یکی از الزامات قطعی طراحی است.
