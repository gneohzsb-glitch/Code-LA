# کنترل دسترسی

ARGUS چند مکانیزم کنترل دسترسی دارد که هر کدام یک سطح متفاوت را محافظت می‌کند: از
دسترسی فایل، تا رمز عملیاتی، تا قفل ماشین.

---

## سطوح دسترسی

| سطح | چه چیزی لازم است | برای چه کاری |
|---|---|---|
| **عضو گروه `argus`** | عضویت در گروه (بدون sudo) | همهٔ دستورهای خواندن: `list`, `tail`, `stats`, `count`, `verify`, `alerts`, `anomalies`, `integrity` |
| **کاربر عادی (خارج از گروه)** | هیچ | هیچ دادهٔ لاگی نمی‌بیند؛ CLI او را به `sudo`/گروه راهنمایی می‌کند |
| **root (`sudo`)** | دسترسی root | نصب، `remove`, `retention` (نوشتن)، `harden`، هر تغییر حالت |
| **رمز حذف** | رمز + توکن | `release`, `remove`, `change-password` |
| **رمزنگاری** | عضویت گروه یا root | خواندن محتوای رمزشده (کلید از `machine.id` + `embedded_salt`) |

---

## گروه `argus` (v15.4)

قبل از v15.4 درخت لاگ `0755/0644` بود — یعنی **هر کاربر عادی روی ماشین کل رکورد
فارنزیک را می‌خواند** (نشتی مستمر محرمانگی). حالا مدل، گروه‌محور است:

| مسیر | مجوز | مالک |
|---|---|---|
| `/etc/argus` | `2750` (setgid) | `root:argus` |
| دایرکتوری‌های لاگ | `2750` (setgid) | `root:argus` |
| فایل‌های لاگ و کلید | `0640` | `root:argus` |

bit **setgid** روی دایرکتوری‌ها یعنی فایل‌ها و زیرپوشه‌هایی که دیمن (root) می‌سازد،
از همان ابتدا گروه `argus` را به ارث می‌برند.

افزودن اپراتور:

```bash
sudo usermod -aG argus <user>     # سپس یک‌بار logout/login
```

- **عضو گروه** → بدون `sudo` می‌خواند (کلید رمزگشایی هم در دسترس است).
- **خارج از گروه** → حتی `stat` روی درخت را ندارد؛ CLI پیام «run with sudo» می‌دهد.
- مدل `0755/0644` عمداً حذف شد (همان نشتی حسابرسی).

انطباق مجوزها با `sudo argus-cli harden --check` قابل بررسی است.

## چه چیزی فقط برای root است؟

| مورد | چرا |
|---|---|
| `remove.key` / `pass.kdf` | `0600`، فقط root؛ هش/مشتق رمز حذف |
| `embedded_salt` | `0640 root:argus`، مهر `immutable`؛ ریشهٔ کلید رمزنگاری |
| `machine.id` | `0640 root:argus`، مهر `immutable`؛ اثر انگشت ماشین |
| `anchor.key` | `0640 root:argus`؛ کلید امضای HMAC برای anchor |

---

## مسیر حذف: دو مرحله‌ای

حذف ARGUS دو چیز می‌خواهد، نه یکی:

1. **رمز حذف** — که هش آن با `remove.key` مقایسه می‌شود.
2. **نوشتن توکن در کرنل** — `shield_release(hash)` توکن را به سپر می‌فرستد.

هیچ‌کدام به‌تنهایی کافی نیست. کسی که فقط فایل `remove.key` را بخواند، نمی‌تواند بدون
رمز این کار را بکند (و کسی که رمز را بداند ولی فایل را نداشته باشد هم — هرچند سپر توکن
زمان بارگذاری را هم می‌پذیرد، تا اپراتور هرگز قفل نشود).

---

## قفل ماشین

سپر و رمزنگاری هر دو به `machine.id` گره خورده‌اند:

```
machine.id = sha256( /etc/machine-id )
```

> **v15.4:** مشتق‌سازی فقط از `/etc/machine-id` است. نسخه‌های قدیمی hostname/MAC/CPU
> را هم داخل می‌بردند؛ آن باعث می‌شد یک تغییر سخت‌افزاری یا نام‌گذاری مجدد،
> لاگ‌های رمزشده را برای همیشه یتیم کند. اگر `/etc/machine-id` نبود، تنها منبع
> جایگزین DMI UUID است.

- کپی لاگ روی ماشین دیگر **قابل رمزگشایی نیست** (کلید مشتق‌شده متفاوت است).
- کپی `remove.key` روی ماشین دیگر هم بی‌فایده است، چون سپر آنجا مسلح نیست.

## جداسازی اختیارات در سطح فایل

| فایل | مجوز |
|---|---|
| `/etc/argus/remove.key`, `/etc/argus/pass.kdf` | `0600` |
| `/etc/argus/machine.id`, `embedded_salt`, `anchor.key` | `0640 root:argus` |
| فایل‌های لاگ روز | `0640 root:argus` |
| آرشیوهای `.log.gz` | `0640 root:argus` + مهر `immutable` |

مهر و برداشتن مهر با ioctl (`FS_IOC_SETFLAGS`) انجام می‌شود، نه `chattr(1)` — چون
`chattr` از طریق `PATH` قابل جایگزینی است و به‌صورت root اجرا می‌شود.

## چه چیزی کنترل دسترسی **نیست**

- ARGUS یک سامانهٔ **مدیریت هویت** نیست.
- **RBAC** ندارد؛ دسترسی بر اساس root/غیرroot است، نه نقش‌ها.
- **جایگزین sudo** نیست؛ از همان مدل دسترسی لینوکس استفاده می‌کند.
