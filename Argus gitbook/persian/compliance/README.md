# انطباق

این بخش توضیح می‌دهد ARGUS چگونه از **استنادپذیری فارنزیک** و **حفاظت از داده** پشتیبانی
می‌کند. هدف، ارائهٔ شواهد فنی برای تیم حقوقی و حسابرسی است — نه ادعای انطباق قانونی.

> **سلب مسئولیت:** ARGUS یک ابزار فنی است. اینکه یک سند در دادگاه یا جلسهٔ انطباق پذیرفته
> شود، به قوانین حوزهٔ قضایی، رویهٔ سازمان، و مشاورهٔ حقوقی بستگی دارد. این صفحه فقط
> قابلیت‌های فنی مرتبط را توصیف می‌کند.

## دو محور

| محور | سؤال | صفحه |
|---|---|---|
| استنادپذیری فارنزیک | آیا این سابقه قابل ارائه به‌عنوان مدرک است؟ | [قابلیت استناد فارنزیک](forensic-admissibility.md) |
| حفاظت از داده | آیا با حریم خصوصی و مقررات داده سازگار است؟ | [حفاظت از داده](data-protection.md) |

## چرا زنجیرهٔ هش برای انطباق مهم است؟

سامانه‌های لاگ سنتی می‌توانند بگویند «این رویداد ثبت شد». ARGUS می‌تواند بگوید
«این رویداد ثبت شد، **و از لحظهٔ ثبت تا حالا دست‌نخورده مانده**» — و این ادعا را با
ریاضیات (زنجیرهٔ SHA-256) اثبات کند، نه با اعتماد به اپراتور.

| ویژگی | ارزش انطباقی |
|---|---|
| زنجیرهٔ هش | اثبات دست‌نخوردگی سابقه |
| مانیفست SHA-256 | مدرک قابل تأیید مستقل (`sha256sum`) |
| لنگر بیرونی | اثبات زمان (سابقه از تاریخ X وجود داشته) |
| مسیر آزادسازی رمزدار | اثبات کنترل دسترسی به خودِ سامانه |
