# برگهٔ مشخصات فنی (Data Sheet)

> **محصول:** ARGUS · **نسخه:** ۱۵٫۴ · **سازنده:** Gneo HZSB
> **پلتفرم مرجع:** Ubuntu 22.04 LTS (کرنل ۵٫۱۵) و Debian 12 (کرنل ۶٫۱)

---

## ۱. معرفی

ARGUS یک سامانهٔ **ثبت رویداد در سطح کرنل** برای کاربرد فارنزیک و حسابرسی امنیتی است. هر
رویداد مهم سیستم را در لحظهٔ وقوع می‌گیرد، به یک بلوک با هش SHA-256 تبدیل می‌کند که به
بلوک قبلی زنجیر شده است، و روی دیسک می‌نویسد. نتیجه یک **زنجیرهٔ دست‌کاری‌ناپذیر** است.

هدف عملی: پس از یک نفوذ یا برای اثبات انطباق، پاسخ به «چه رویدادی، توسط چه کاربر/فرآیندی،
کِی، و آیا کسی لاگ را دست‌کاری کرده است یا نه».

---

## ۲. قابلیت‌های کلیدی

| قابلیت | توضیح |
|---|---|
| ثبت در سطح کرنل | حسگر eBPF، ۲۱ syscall کلیدی (فایل، مجوز، ماژول، سیگنال) |
| زنجیرهٔ هش | `h = SHA-256(prev_hash + event + timestamp + uid + pid)` |
| مقاومت در برابر دست‌کاری | سپر کرنل (۴ kprobe) + مهر `immutable` روی آرشیوها |
| فیلتر نویز هوشمند | خواندن‌های روتین ثبت نمی‌شوند؛ نوشتن روی همان مسیرها ثبت می‌شود |
| تجمیع رویداد | خواندن‌های تکراری در یک بلوک خلاصهٔ شمارش‌دار جمع می‌شوند — **حذف نمی‌شوند** |
| پرچم مسیر حساس | دسترسی به `/etc/shadow`، کلیدهای SSH، `/root/` و… پرچم‌دار می‌شود |
| نگهداشت بی‌اتلاف | روزهای گذشته فشرده می‌شوند، **هرگز حذف نمی‌شوند**، و مهر می‌خورند |
| رمزنگاری اختیاری | AES-256-CBC با کلید قفل‌شده به ماشین (PBKDF2-HMAC-SHA256) |
| صدور به SIEM | خروجی JSON/CSV + فوروارد زندهٔ syslog با تگ `ARGUS_SENSITIVE` |
| گواهی یکپارچگی | مانیفست SHA-256 برای یک بازهٔ زمانی (مدرک قابل ارائه) |
| لنگر بیرونی | فرستادن سر زنجیره به مقصد بیرونی برای اثبات زمان |

## ۳. معماری

سه لایه، با کل منطق در فضای کاربر؛ در کرنل فقط یک حسگر eBPF و یک ماژول سپر کوچک.

```
┌─────────────────────────────────────────────────────────────┐
│  ۱. حسگر eBPF  (argus_sensor.bpf.c)                          │
│     ۲۱ هوک، فقط ثبت — بدون هش، بدون ذخیره، بدون تصمیم        │
│     تأییدشده توسط verifier کرنل پیش از اجرا                  │
└───────────────────────────┬─────────────────────────────────┘
                            │ ring buffer
┌───────────────────────────▼─────────────────────────────────┐
│  ۲. دیمن (capture engine) — فضای کاربر                       │
│     فیلتر/طبقه‌بندی → بلاکچین SHA-256 → ذخیره → هشدار → export │
│     + نگهداشت، لنگر بیرونی، تفکیک IP                         │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  ۳. لایهٔ حفاظت (ماژول سپر) — ۴ kprobe                       │
│     kill / tkill / tgkill / delete_module                    │
└─────────────────────────────────────────────────────────────┘
```

## ۴. الزامات استقرار

| مورد | حداقل |
|---|---|
| سیستم‌عامل | Ubuntu 22.04 LTS یا Debian 12 (کرنل ۵٫۱۵+) |

| رمز/سرویس | systemd |

**بدون تغییر GRUB. بدون ریبوت** — نه برای نصب، نه برای به‌روزرسانی، نه برای حذف.

## ۶. مدل امنیتی

**چه چیزی محافظت می‌شود:** دیمن را نمی‌توان با `kill`/`killall`/`killpg` کشت و ماژول را
نمی‌توان با `rmmod` یا `rmmod -f` برداشت. سیگنال از PID 1 (systemd) عمداً عبور می‌کند تا
`systemctl stop/restart` و به‌روزرسانی بدون رمز ممکن باشد.

**مسیر آزادسازی (بدون ریبوت):** توکن = هش SHA-256 رمز حذف در `/etc/argus/remove.key`.
بدون این فایل، سپر **اصلاً بار نمی‌شود** — تا هیچ‌وقت سیستمی قفل نشود که فقط با ریبوت
باز شود.

**قفل ماشین:** سپر و رمزنگاری هر دو به `machine.id` گره خورده‌اند.

**مهر آرشیو:** هر روزِ فشرده‌شده با پرچم `immutable` مهر می‌شود؛ با `chattr -i` و بدون
ریبوت باز می‌شود.

**تاب‌آوری دیمن:** واحد systemd با `Restart=always`؛ کرش دیمن، کرنل را تحت تأثیر قرار
نمی‌دهد.

**محدودیت پذیرفته‌شده:** سپر در برابر root مصمم ادعایی ندارد (root می‌تواند `cgroup.kill`،
`reboot` یا `kexec` کند). هدف، بالا بردن هزینه و مسدود کردن مسیرهای بدیهی است.

## ۷. یکپارچه‌سازی

- **SIEM:** فوروارد زندهٔ syslog؛ رویدادهای مسیر حساس با تگ `ARGUS_SENSITIVE`. مقصد:
  `FILE:` / `TCP:` / `UDP:`.
- **خروجی دستی:** `argus-cli export --format json|csv` (ستون `flags`).
- **گواهی مدرک:** `argus-cli integrity --from DATE --to DATE`.
- **API زنجیره:** `argus-cli verify` و `argus-cli block N`.
- **بلوک‌های خلاصه و پیکربندی:** `AGGREGATE`، `CONFIG`، `MODE_CHANGE`، `MAINTENANCE` هم در
  همان زنجیره و با همان فرمول هش ثبت می‌شوند.

## ۸. بهره‌برداری

```bash
# نصب
sudo ./install.sh

# روزمره
argus-cli status            # وضعیت سپر، دیمن، رمز، مصرف دیسک
argus-cli verify            # تأیید زنجیره (لینک + هش)
argus-cli list --sensitive  # فقط رویدادهای مسیر حساس
argus-cli sensitive         # همان فیلتر، به‌صورت دستور مستقل
argus-cli tail              # نمایش زنده
argus-cli mode              # حالت فیلتر تجمیع (بدون ریبوت)
argus-cli retention         # سیاست نگهداشت

# به‌روزرسانی بدون ریبوت
sudo argus-cli service restart

# حذف (لاگ‌ها دست‌نخورده می‌مانند)
sudo argus-cli remove
```

رمزنگاری لاگ اختیاری است: `ENCRYPT=1` در `/etc/argus/export.conf` و ری‌استارت سرویس.
