# زنجیرهٔ هش

هستهٔ دست‌کاری‌ناپذیری ARGUS، **زنجیرهٔ هش** است. هر رویداد به یک بلوک تبدیل می‌شود که
هش آن، هش بلوک قبلی را در خود دارد. این وابستگی، حذف یا ویرایش بی‌سروصدای هر بلوکی را
غیرممکن می‌کند.

---

## قاعدهٔ هش

```
h = sha256( prev_hash + event + timestamp + uid + pid )
```

- `prev_hash` هش بلوک قبلی است.
- **بلوک اول** هر زنجیره `prev_hash` = ۶۴ صفر دارد (جنسیس).

> **نکتهٔ مهم:** فیلد `f` (پرچم حساس) عمداً **جزء ورودی هش نیست**. این تصمیم فرمول هش را
> از نسخه‌های قبل دست‌نخورده نگه می‌دارد، پس همهٔ بلوک‌های تاریخی معتبر می‌مانند.

---

## فرمت بلوک

هر بلوک یک خط JSON است:

```json
{"t":1790795115,"e":"openat: /etc/passwd flags=0","ph":"<64 hex>","h":"<64 hex>",
 "u":0,"p":1234,"pp":1,"c":"cat","hn":"host","un":"root","ip":"127.0.0.1"}
```

| فیلد | معنی |
|---|---|
| `t` | timestamp (دیوار، ثانیه) |
| `e` | متن رویداد (هش‌شده) |
| `ph` | هش بلوک قبلی |
| `h` | هش این بلوک |
| `u` | uid |
| `p` | pid |
| `pp` | ppid |
| `c` | نام فرآیند (`comm`) |
| `hn` | hostname |
| `un` | نام کاربر |
| `ip` | IP بیرونی مرتبط (در صورت وجود) |
| `f` | پرچم (حساس)، **هش‌نشده** |

---

## انواع بلوک

ARGUS چند نوع بلوک تولید می‌کند که همه با **همان فرمول هش** زنجیر می‌شوند:

| نوع | منبع | کاربرد |
|---|---|---|
| رویداد عادی | `blockchain_add_event()` | هر syscall ثبت‌شده |
| `AGGREGATE` | `blockchain_add_synthetic()` | خلاصهٔ شمارش‌دار خواندن‌های تجمیع‌شده |
| `AGGREGATE-RECOVERED` | `blockchain_add_synthetic()` | بازیابی sidecar یتیم پس از crash |
| `CONFIG` | `blockchain_add_synthetic()` | هش allowlist + حالت + پنجره هنگام تغییر |
| `MODE_CHANGE` | `blockchain_add_synthetic()` | تغییر حالت فیلتر |
| `MAINTENANCE` | `blockchain_add_synthetic()` | اقدام نگهداشت (حالت `archive`/`auto`) **پیش از** انجام |

بلوک‌های synthetic تایم‌استمپ **ساعت دیوار** دارند (نه مونوتونیک)، چون پنجره‌ای را
توصیف می‌کنند که بسته شده و مهر monotonic حسگر ندارد. **هیچ فیلد جدیدی به فرمول هش
اضافه نشد**، پس همهٔ بلوک‌های قبلی معتبر می‌مانند.

---

## چرا این کار می‌کند؟

اگر مهاجم بخواهد بلوک میانی شمارهٔ `k` را حذف یا ویرایش کند:

1. هش بلوک `k` عوض می‌شود (چون محتوا عوض شده).
2. بلوک `k+1` هنوز `ph` قدیمی را دارد → **شکاف لینک**.
3. اگر مهاجم `ph` بلوک `k+1` را هم به‌روز کند، هش بلوک `k+1` عوض می‌شود → شکاف به `k+2`
   منتقل می‌شود.
4. برای پنهان‌کردن کامل، باید تا آخر زنجیره همه را بازمحاسبه کند — که یعنی عملاً
   بازنویسی کل سابقه.

`argus-cli verify` هم **لینک** و هم **هش** را بازمحاسبه می‌کند، پس هر سه حمله کشف
می‌شوند:

| حمله | کشف با |
|---|---|
| ویرایش محتوای یک بلوک (هش دست‌نخورده) | `BAD HASHES` |
| جابه‌جایی/دوباره‌لینک‌کردن یک بلوک | `BROKEN LINKS` |
| حذف یک بلوک از میانه | `BROKEN LINKS` |

---

## بازیابی پس از ری‌استارت

هر ری‌استارت دیمن، اگر زنجیره را از ابتدا شروع کند، آن را می‌شکند. ARGUS هنگام بالا
آمدن، آخرین بلوک `.log` (یا `.log.gz`) روز را می‌خواند و `prev_hash` را از آن ادامه
می‌دهد. این یکی از باگ‌هایی بود که در مسیر توسعه رفع شد (مورد ۷٫۱۳).

---

## محدودیت ظرفیت در حافظه

دیمن یک حد نگه‌داری در حافظه دارد (FIFO) ولی هر بلوک بی‌درنگ روی دیسک نوشته می‌شود؛
بنابراین حافظه هرگز سقف واقعی سابقه نیست. سابقه روی دیسک است و توسط `verify` و `list`
خوانده می‌شود.
