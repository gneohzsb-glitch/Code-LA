# Benchmarks

All numbers below were measured on the **reference VM**: Ubuntu 22.04 LTS, kernel
`5.15.0-171-generic`, virtual disk. Values on real hardware may be better or worse.

---

## Recording rate

| Mode | Rate (30 seconds) |
|---|---|
| Pre-filter (raw) | ~326 blocks |
| Post-noise-filter | **~36 blocks** |

In other words, the noise filter reduces volume by roughly **9×** without losing valuable
events — only routine reads (`/proc`, libraries, …) are discarded, while every write is kept.

---

## Self-capture events

| Metric | Value |
|---|---|
| Events generated by the daemon itself | **0** |

The daemon never records its own events (the `daemon_pid_map` map in the sensor). Without
this, an endless feedback loop would occur.

---

## Retention compression

| Metric | Value |
|---|---|
| Size before compression | 46 MB |
| Size after compression | 8.4 MB |
| Ratio | **5.4×** |
| Bytes discarded | 0 |

Compression is lossless: every byte is preserved, just in a smaller format.

---

## CLI command speed

| Command | Input | Time |
|---|---|---|
| `list --external` | 109 MB day | **~0.6 seconds** |
| `verify` | 368,137 blocks | **~3.4 seconds** |
| `count` | Whole tree | A few seconds (reads all history) |
| `status` | — | Immediate |

`list --external` uses an open-addressing table (no cap) and has eliminated the extra
`wc -l` pass, so it answers on a full day in under a second.

---

## System overhead

| Source | Cost |
|---|---|
| eBPF sensor | Minimal (ring buffer only) |
| Kernel shield | 4 kprobes; active only on the signal/removal paths |
| Daemon | One userspace process with background threads |
| Adding each event | A single JSON-line write |

With an empty allowlist (the default), the cost of aggregation in the hot path is a single
comparison, and no event is aggregated.

---

## What is **not** measured

Honesty requires saying this as well:

| Item | Status |
|---|---|
| Overhead under a real database/web load | Not measured |
| Behaviour on a high-speed NVMe disk | Not measured |
| Multi-thousand-process scale | Not measured |
| Daemon CPU use under heavy load | Not measured |

These should be measured on a real host. The numbers on this page convey an **order of
magnitude**, not an SLA.
